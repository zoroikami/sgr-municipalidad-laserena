Diagrama de Requerimientos: 
Descripción 
Es una representación gráfica de los requerimientos funcionales y no funcionales de un sistema, 
mostrando su organización, jerarquía y relaciones. Permite visualizar de manera estructurada qué 
necesidades debe satisfacer la solución. 
Propósito 
• Identificar y organizar los requerimientos del proyecto. 
• Mostrar la descomposición de requerimientos generales en requerimientos más 
específicos. 
• Facilitar la comunicación entre clientes, usuarios y equipo de desarrollo. 
• Servir como base para la definición de casos de uso, diseño y pruebas.

Caso de Uso de Alto o Nivel o General: 
Descripción 
Es una representación simplificada de las funcionalidades principales del sistema y de los 
actores que interactúan con él. Se enfoca en mostrar qué hace el sistema, sin detallar el proceso 
interno de cada funcionalidad. 
Propósito 
• Proporcionar una visión global del sistema. 
• Identificar actores y funcionalidades principales. 
• Delimitar el alcance del proyecto. 
• Facilitar la comprensión inicial de los requerimientos por parte de los interesados. 
Componentes principales 
• Sistema. 
• Actores. 
• Casos de uso principales. 
• Relaciones entre actores y casos 
de uso.

Caso de Uso Detallado 
Descripción 
Es la especificación completa de un caso de uso particular, describiendo paso a paso cómo 
interactúan el actor y el sistema para lograr un objetivo determinado. 
Propósito 
• Documentar el comportamiento esperado del sistema. 
• Reducir ambigüedades en los requerimientos. 
• Servir de base para el diseño, la programación y las pruebas. 
• Definir escenarios normales y alternativos. 
Información que suele contener 
• Nombre del caso de uso. 
• Objetivo. 
• Actor(es). 
• Precondiciones. 
• Flujo principal. 
• Flujos alternativos. 
• Postcondiciones. 
• Reglas de negocio.

Cuadros de Descripción de Casos de Uso 
Descripción 
Es una plantilla tabular utilizada para documentar de manera estructurada la información de un 
caso de uso detallado. Resume todos los elementos relevantes en un formato estandarizado. 
Propósito 
• Estandarizar la documentación de casos de uso. 
• Facilitar la revisión y validación de requerimientos. 
• Mantener la trazabilidad entre requerimientos y funcionalidades. 
• Servir como referencia para desarrolladores y evaluadores.

Relación entre los artefactos 
En otras palabras, el diagrama de requerimientos identifica qué necesita el sistema; el caso de 
uso general muestra las funcionalidades principales; el caso de uso detallado  describe cada 
funcionalidad paso a paso; y el cuadro de descripción de caso de uso  documenta formalmente 
esos detalles en una plantilla estructurada. 
En conjunto, estos artefactos proporcionan la trazabilidad necesaria entre los requerimientos y el 
diseño del sistema. Su análisis permite determinar las funcionalidades que deberán 
implementarse, las interacciones entre usuarios y sistema, los datos a cap turar y visualizar, así 
como las reglas de negocio involucradas. Como resultado, constituyen la base para la elaboración 
de prototipos de interfaces de usuario (UI), wireframes, mockups y diseños de experiencia de 
usuario (UX)  que representen de forma coherente las necesidades identificadas durante el 
levantamiento y especificación de requerimientos. 
 
Propuesta de trazabilidad: 
 
Entonces los mockups deben representar las pantallas necesarias para ejecutar los casos de uso 
del diagrama y también contemplar los escenarios alternativos modelados.
